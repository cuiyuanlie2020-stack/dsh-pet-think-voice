## 四条硬规则（来自 `dev-standards/01-仓库与分支规范.md` §3.1）

| # | 规则 | 为什么 |
|---|---|---|
| **E1** | 只从 `main` 拉 `exp/<name>` | 从别的实验分支拉 ⇒ 结果叠加了两个变量，无法归因 |
| **E2** | **一次只改一个变量** | 同时动两个变量会让整批数据作废 |
| **E3** | 必须有台账 `experiments/<name>/README.md` | 三个月后你自己也说不清哪个组合赢在哪 |
| **E4** | 结束（无论成败）**必须给结论**：合并 or 删除 | 长期挂着的实验分支就是死代码温床 |

## 纪律补充

- ⚠️ `experiments/` 下的复现命令**必须能重跑**。没有复现命令的实验结果，三个月后无法验证，等于没做。
- 实验工作区用 `git worktree add ../<项目名>-exp-<name> exp/<name>`，**不要**放主仓库内部（会被 `git status` 当成未跟踪目录）。
