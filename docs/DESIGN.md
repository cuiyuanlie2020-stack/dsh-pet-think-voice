## 1. 一句话定位

**给 DSH（DeepSeek Harness）挂一只会说话的鲸鱼娘桌宠：实时抓取模型的思考内容（reasoning），挑出其中"有戏"的片段，用 Live2D 形象 + 语音念出来，让长时间 vibecoding 不无聊。**

### 1.1 差异化（本项目的立身之本）

社区插件已经覆盖了两头，**唯独漏掉了中间这个组合**：

| 社区已有               | 例子                                                 | 与本项目的关系                          |
| ------------------ | -------------------------------------------------- | -------------------------------- |
| 朗读**回复**           | `dsh-plugin-tts`、`dsh-voice-mini`、`dsh-read-aloud` | 读的是 `content`，**不是** `reasoning` |
| 展示**思考**           | `dsh-thinking-summary`、`dsh-think-expand`          | 只做文字摘要/展开，**不发声**                |
| 桌宠壳                | `dsh-pet-live2d`、`dsh-desktop-pet`                 | 状态展示/摸头，**不读思考**                 |
| **读思考 + 拟人化 + 发声** | ——                                                 | ✅ **本项目（社区空白）**                  |

### 1.2 目标用户

- 主要：长时间用 DSH 写代码、且愿意开声音的开发者（vibecoding 场景）
- 次要：想给自己的 DSH 加个性化桌宠的社区用户
- ⚠️ **不假设用户有 GPU 或本地模型**（见 R3）——社区插件必须开箱即用

## 2. 设计红线（违反即返工）

| #      | 红线              | 说明                                                            | 适用范围（边界！）                              |
| ------ | --------------- | ------------------------------------------------------------- | -------------------------------------- |
| **R1** | **不与用户的主力负载竞争** | 插件在稳态下的额外占用必须低于 DESIGN 7.4 的阈值表；任何环节**不得在显存中长期驻留模型权重**。       | 全链路。⚠️ 不适用于「用户显式开启可选高级功能」的场景           |
| **R2** | **只读思考，不读正文**   | 只消费 `reasoning` 文本流，不消费 `content`。                            | 采集层。⚠️ 可读工具调用名（用于相位判断），但**不得朗读**工具产出内容 |
| **R3** | **零本地依赖**       | 用户**不装任何本地模型/服务**（无 Ollama、无 TTS 权重、无 Python 环境）时，插件功能必须完整可用。 | 插件默认路径。降级必须**留痕提示**，不得静默               |
| **R4** | **许可物理隔离**      | MIT 代码与 CC BY-NC-SA 美术资源必须**分目录存放**，不得混同一份 LICENSE 下。         | 仓库结构                                   |
| **R5** | **可一键停**        | 用户必须能随时静音 / 暂停朗读 / 彻底关闭插件，无需卸载。                               | 交互层                                    |

> ⚠️ **边界写不清就会被误用**（教训来自 plotengine）：R1 的"不竞争"**只管插件自身**，不禁止用户在完全空闲时开启可选高级功能；R2 的"不读正文"**只管朗读内容**，不禁止用正文事件判断相位。

### 3.1 目标（本项目要达成）

| #  | 目标         | 可观察判据                                   |
| -- | ---------- | --------------------------------------- |
| G1 | 能拿到思考原文    | 插件日志/气泡出现真实 reasoning 片段                |
| G2 | 挑得出"有戏"的片段 | 命中率 ≥ 规则词表可解释，噪声片段不朗读                   |
| G3 | 念得出来       | 命中片段 ≤3s 内开始播放语音                        |
| G4 | 形象会动嘴      | 朗读时 Live2D 口型随音频包络开合                    |

## 4. 系统架构

### 4.1 插件形态与双半区结构

DSH 插件天然是**双半区**（本项目沿用 `dsh-pet-live2d` 的既有结构，不改）：

| 半区          | 文件                     | 运行环境             | 本项目职责                              |
| ----------- | ---------------------- | ---------------- | ---------------------------------- |
| **host**    | `lib/index.js`         | Node（DSH 服务端）    | 订阅会话事件、提取思考文本、筛选、调 TTS、通过 SSE 下发指令 |
| **browser** | `lib/client.js`        | 浏览器（DSH Web GUI） | 接收 SSE、渲染 Live2D、播放音频、驱动口型、显示气泡    |
| **vendor**  | `lib/live2d-vendor.js` | 浏览器              | pixi.js + Live2D 引擎（**不改则不需重新构建**） |

> 上表路径**相对插件包根**——D8 落地后**仓库根即插件包根**（上游包已入仓并改名，见 HANDOFF §6）。本项目**不改**上游这三个文件的边界划分。

### 4.2 数据流

```
DSH 会话事件流
      │
      ▼
① [采集] host：从 reasoning 文本流提取原始思考          ← ✅ 已验证（P0-1，见 6.1）
      │
      ▼
② [切分] 领域层：长思考切成语义完整的小片段              ← ⚠️ 刚需：实测思考中位 1295 字
      │
      ▼
③ [筛选] 领域层：规则粗筛（降噪~90%）→ 可选小模型打分
      │
      ▼
④ [拟人化] 领域层：挑出"有戏"的表达，必要时加语气提示
      │
      ▼
⑤ [节流] 应用层：频率控制、去重、排队（默认 **20s** 一句，D3 已定）
      │
      ▼
⑥ [合成] 基础设施：TTS provider（**Edge 云端，零本地依赖、零 npm 依赖**）
      │
      ▼
⑦ [下发] host：新增 `speak` 帧，经既有 SSE 通道推送
      │
      ▼
⑧ [呈现] browser：气泡显示文字 + 播放音频 + 口型同步 + 表情联动
```

> ⚠️ ⑥ 是全链路**唯一依赖外网**的环节。网络不可用时降级为**只显示气泡文字**（红线 R3，须留痕提示）。

### 4.3 分层与目录职责

按四层模型映射到 DSH 插件的双半区（**依赖必须单向向下**）：

| 层          | 本项目的落点                                                                                      | 职责                                 | 禁止                         |
| ---------- | ------------------------------------------------------------------------------------------- | ---------------------------------- | -------------------------- |
| **① 入口**   | host：`registerRoutes` 路由、`attachActivityEvents` 订阅<br />browser：`slots` 注册、`EventSource` 接收 | 只做参数校验 / 事件转发 / 调用应用层              | 写业务逻辑                      |
| **② 应用**   | `lib/app/` 编排层                                                                              | 编排采集→切分→筛选→节流→合成的完整流程              | 直接调外部 API（须经 infra）        |
| **③ 领域**   | `lib/core/`（**项目最值钱的部分**）                                                                   | 纯逻辑：文本切分、有趣度打分、台词拟人化。**零框架依赖、可单测** | import pixi / DSH API / 网络 |
| **④ 基础设施** | `lib/infra/`                                                                                | TTS provider、SSE 广播、文件访问、**负载探针**  | 含业务判断                      |

> ⚠️ 领域层（`lib/core/`）必须能脱离 DSH、脱离浏览器**单独跑单测**——这是本项目唯一能沉淀成资产的层，不允许被框架污染。

## 5. 核心领域模块设计（`lib/core/`）

这是项目最值钱的部分，**7 个模块**，全部纯逻辑、可单测：

| 模块                  | 职责                              | 关键输入 → 输出                  | 状态                  |
| ------------------- | ------------------------------- | -------------------------- | ------------------- |
| `ThinkingExtractor` | 从会话事件里提取 reasoning 原始文本         | `session event` → `string` | ✅ **已验证**（P0-1）     |
| `FragmentSplitter`  | 长思考切成语义完整、适合朗读的小片段              | `string` → `Fragment[]`    | **刚需**（见下）          |
| `InterestScorer`    | 判定片段"有趣度"（规则 + 可选模型）            | `Fragment` → `score 0..1`  | 规则设计已定，词表已两轮校准（§5.1.1 / §5.1.2） |
| `LinePolisher`      | 拟人化（清洗 + 裁齐 + 产出 emotion 标签）    | `Fragment` → `Line`        | ✅ **P4-2 完成**（见 §5.2） |
| `SpeechPlanner`     | 节流 / 去重 / 排队 / 频率控制 / **回应负载闸** | `Line[]` → `SpeakTask[]`   | ✅ P2-5（20s 闸，D3 已定） |
| `ReasoningLanguage` | 思考语种策略 / 注入文案 / 语种检测 / **音色解析** | `policy` → `resolver`      | ✅ P3-0（音色**由策略决定且整场恒定**） |
| `LoadGate`          | 负载闸判定：超阈值**持续** N 秒 ⇒ 静默，回落 ⇒ 恢复 | `sample, now` → `{silent}` | ✅ P3-5（采样在 `lib/infra/load-probe.js`） |

> ⚠️ **实测约束（P0-1，对 181 条真实思考统计）**：思考长度 **中位 1295 字**、最长 **14994 字**。  
> 含义：**切分与长度上限是刚需，不是可选优化**——一条思考按朗读速度能读十几分钟，不切分就没法用。  
> `dt[]`（逐 token 毫秒增量）是模型**吐字**的节奏，**不得**直接当朗读节奏用；它只能作为"哪里停顿过"的线索。

### 5.1 `InterestScorer` 的两级策略

| 级     | 手段                           | 成本（实测见 RESOURCE-BUDGET） | 作用                    |
| ----- | ---------------------------- | ----------------------- | --------------------- |
| 第 1 级 | 规则 + 情绪词表                    | **0** 显存 / **0** 模型调用   | **降噪 ~90%**，秒杀明显无趣的片段 |
| 第 2 级 | 本地小模型（qwen3:1.7b，**可选、默认关**） | ~2GB 显存 / 需用户自装 Ollama  | 对候选片段打"有趣度"分，只读高分     |

**第 2 级是可选增强，不是必需**（红线 R3）。默认只跑第 1 级。⚠️ **低配用户（8G 显存）不应开启第 2 级**——它是本插件唯一会占用显存的环节。

**触发特征** —— ⚠️⚠️ **2026-10-11 实测推翻了这里的两条原假设**（原版是拍脑袋的"初版假设"）：

| 原假设 | 实测结果 |
|---|---|
| 思考是中文的 | ❌ **错**。212 条真实思考：中文只占 **5.2%**，ASCII 字母占 **67.3%**。按条判定**英文主导 76%**、中文主导仅 **7%** |
| 四类情绪词（中文）能筛出"有戏"片段 | ❌ **错**。`原来`/`懂了`/`想了通`/`哎`/`绕了一大圈`/`白折腾` 在真实数据上触发 **0 次** —— 因为语种就选错了 |

实测**实际可触发**的信号（命中片段数 / 4714 个片段）：

| 桶 | 中文 | 英文 |
|---|---|---|
| 自我怀疑 | `等等` 11 · `不对` 1 | `hmm` 208 · `wait` 84 · `reconsider` 12 · `wrong` 11 |
| 顿悟 | （全部 0） | `interesting` 20 · `understand` 6 · `I see` 4 |
| 吐槽 | （全部 0） | `messy` 1 · `weird` 1 · `ugh`/`tricky`/`messy` 基本 0 |
| 犹豫权衡 | `还是` 8 · `要不` 2 | `maybe` 173 · `alternatively` 15 · `either` 10 · `perhaps` 7 |

⇒ **该模型的思考是"临床式"的，情绪标记极其稀薄**，可念素材天然偏少且集中在"自我修正"一类。
⇒ 词表已按实测改为**双语**，实现见 `lib/core/interest-scorer.js`（词表独立导出，D2 校准只改数据不动逻辑）。
⇒ **阈值必须看"目标片段能否过闸"再定**：先取 0.62 时发现单个真实信号最高只有 ~0.51 —— 高到必须两类信号叠加才过，等于把最典型的自我修正全滤掉。现取 **0.50**。

### 5.1.1 ⚠️ P4-1 中文词表重校（2026-10-11，D11 收口）

**问题**：D10 定了「让思考变中文」后，真机实测 `片段=8 过阈=0 最高分0.29/阈值0.5` ——
**默认配置下宠物永远没声音**。上面那版词表是**英文语料**校准的。

**根因（推翻了"阈值太高"这个直觉判断）**：逐词体检 4714 个片段，**61 个词条里 37 个零命中**：

| 桶 | 中文侧原词条 | 实测 DF |
|---|---|---|
| 顿悟 | `原来` `懂了` `想通` `明白了` `知道了` `恍然大悟` | **全部 0** |
| 吐槽 | `哎` `绕了一大圈` `白折腾` `这坑` `无语` `离谱` | **全部 0** |
| 自我怀疑 | `我搞错` `搞错` `反了` `弄错` `看错` | **全部 0**（仅 `等等` 10 / `不对` 1） |
| 犹豫权衡 | `权衡` `纠结` | **全部 0**（`还是` 14 / `要不` 8 有效） |

英文侧同样有 20 个僵尸（`tricky` `makes sense` `got it` `ugh` `turns out` `unsure` `trade-off`…）。
⇒ 这些词不会让代码报错，只会让人误以为"这桶有覆盖"，**掩盖真实缺口**。

**第二个推翻**：**中英的"有戏"不是一个体系**，不能互译。

| | 英文侧 | 中文侧 |
|---|---|---|
| 主要形态 | **情绪词** | **自语式判断 / 转折** |
| 实测高频 | `actually` 282 · `hmm` 208 · `wait` 84 | `结论` 51 · `说明` 48 · `其实` 22 · `待实测` 12 |
| 情绪词 | 稀疏但存在 | **几乎不存在**（`哎`/`无语`/`离谱`/`纠结` 全 0） |

中文原文样例：`其实先别乱跑命令` · `不过等一下，还有一点值得确认` ·
`结论：当前用的是官方账号通道` · `置信度：中（…未实测复算）`

**改动**：剔除 37 个零命中词条（含 **15 个英文**）+ 3 个低效词（共 40）；按 **DF≥5** 补入 17 个中文词（`其实`/`实际上`/`待实测`/`等等`/
`未实测`/`疑点`/`结论`/`说明`/`根本原因`/`坑`/`嗯`/`不过`/`或者`/`值得`/`还是`/`除非`/
`要不要`/`至少`/`或许`）。**阈值、权重、罚则、逻辑一律未动**。

| 指标 | 重校前 | **重校后** |
|---|---|---|
| 中文语料过阈率 ≥0.50（2111 片段） | 4.4% | **10.4%** |
| 全量语料过阈率（4714 片段） | 7.6% | 9.3% |
| 正例护栏（中英各半，5 条） | —— | **5/5 全过** |
| 噪声护栏（代码/路径/符号） | 0.00~0.26 | 0.00~0.26（不变） |

**为什么阈值不动**：未过阈片段的归因显示 **87% 是"命中但不够"**（不是"没命中"），
补词后这一批自动上来。靠降阈值凑数量会同时放进大量噪声。

> ⚠️ **`说明` / `结论` 偏泛，会有少量误报 —— 这是刻意的取舍**：先拿到音量，
> 误报交给 P2-5 的 20s 频率闸（上限 3 条/分钟）挡，而不是在这里靠高阈值误杀主体。
> 真实听感须由人判定（PLAN P4-2 / P4-5）。
>
> ⚠️ **重校只证明「选得出片段」，不等于「念出来好听」**。

### 5.1.2 ⚠️ 换用 WorkBuddy 本地对话做主语料（2026-10-11 同日续做，**修正了 5.1.1 的一部分**）

**触发**：用户提示「本地 workbuddy 里的对话也是语料；我很多时候用 ds 模型」。

**语料源规模对比**（`p0/scan-workbuddy-sessions.py`）：

### 5.2 `LinePolisher`（P4-2 拟人化，2026-10-11）

**职责**（DESIGN §4.2 的第 ④ 步）：把一条**已过阈**的片段收拾成"能开口念的一条台词"，
并给出**表情标签**。落点 `lib/core/line-polisher.js`（30 例单测）。

#### 5.2.1 🔴 第一条铁律：**只挑只裁，绝不改字**

用户 2026-10-11 拍定：改写的上限是"清洗 + 裁齐"，**不允许插入模型没想过的词**
（不做「嗯…」语气词包装、不补标点、不做同义替换）。

理由：R2 的立身之本是"**读**模型的思考"。一旦加词，宠物念的就不再是模型的思考，
而是我们编的台词 —— 观众以为宠物在转述，其实在演戏。

⇒ 这条被一个**可执行的不变量**守着（`line-polisher.test.js`）：
**把输出与输入的空白全部去掉后，输出必须是输入的子序列。**
任何"插入字符"的改动都会当场把它顶红 —— 包括以后有人想加个「诶？」。
允许的动作只有四类，**全部是删除**：去 Markdown 标记 / 去 emoji 与零宽字符 /
合并空白 / 裁掉悬挂残句。

#### 5.2.2 它修的两个真实缺陷

| 缺陷 | 现象 | 处理 |
|---|---|---|
| **D12 片段边界** | 真机抓到实际朗读文本 `", being honest about confidence levels and what still needs "` —— 切分器切在句子中间，打分器只看关键词不看完整性，一路绿灯走到 TTS | 首部悬挂标点剥掉；无句界且以悬挂词/悬挂标点收尾 ⇒ **拒收**；尾部半截（≤12 字）裁到最近句界 |
| **Markdown 标题** | `## 结论：不是卡住…` 念出来是"井号井号 结论" | §7.7.4 已在**打分侧**扣分让标题过不了阈；本模块做**第二道兜底**（判据相同、实现独立）。打分阈值将来若被调低，标题不会重新漏到耳朵里 |

#### 5.2.3 表情标签：直接用**模型自己的表情 key**

不搞"抽象语义标签再映射"那一层，直接用 `pets/ds-whale-girl/catalog.json` 里
`category=emotion` 的 20 个 key（脸红 / 星星眼 / 问号 / 生气 / 调皮 / 吐舌 …）。
⇒ P4-3 是**零映射**直通，少一处"两边对不上却谁都不报错"的隐患。

标签来源是**打分器已经算出来的命中桶**（`interest-scorer` 的 `buckets` / `matches`），
不重新做一遍关键词匹配 ⇒ "为什么念这句"与"为什么演这个表情"**同源**。

| 桶 | 表情 |
|---|---|
| 情绪外露（偷懒/降级） | 调皮 |
| 情绪外露（阴阳怪气） | 吐舌 |
| 吐槽 | 生气 |
| 顿悟 | 星星眼 |
| 自我怀疑 | 问号 |
| 犹豫权衡 | 呆呆眼 |
| _（无桶命中）_ | `null`（靠"疑问号+长度"过阈的片段没有情绪可言，不硬凑） |

多桶同时命中时按**戏剧性**取用（`情绪外露 > 吐槽 > 顿悟 > 自我怀疑 > 犹豫权衡`），
**不是**按打分权重 —— `wait, … I see now` 的戏核在顿悟上，该演星星眼而不是问号。
⚠️ 但若高优先桶**给不出表情**（例如只命中了被静音的 `说明`），要**让位给下一个桶**，
而不是直接放弃整句的表情 —— 详见 §5.2.4 的 D15。

#### 5.2.4 ⚠️ 桶内**逐词纠偏**：桶太粗时用词本身修正表情

**只纠表情，不动打分**（词仍留在原桶参与打分，阈值与通过率一点没碰）。
两种落法：**换一个表情**（`WORD_EXPRESSION`）与**整句不演**（`SILENT_WORDS`）。

证据来自 `p0/polish-probe.mjs` 在 **37.9 万片段**（过阈 30394）上的**逐词归因表**：

| 词 | 条数 | 它其实是 | 结论 |
|---|---|---|---|
| `其实` `实际上` | **6698**（占放行 22%） | **澄清与确证**（"实际上是这么回事"）；逐词抽样 28 条**无一条**是"我搞错了" | ❌ 不该推「问号」→ 改推**感叹号** |
| `等等` `wait` `hmm` `wrong` `reconsider` `不对` | 约 1.2 万 | 真怀疑 / 自我修正 | ✅ 保持「问号」 |
| `actually`（英文） | 4866 | 英文里多是"等等，其实是…"的**修正**标记 | ✅ 保持「问号」 |
| `说明` | **7730**（推了 **5699** 条「星星眼」＝占放行 18.9%） | 抽样 14 条逐条数：**7 条元信息 · 6 条推断 · 1 条无法判定** | ⚠️ **整句不演**（D15，用户拍定） |

不做纠偏时「问号」会吃掉 **63%** 的放行片段 —— 宠物会一脸疑惑地念
`实际上，用户提供的总结非常详细` 这种平铺直叙的陈述句。纠偏后降到 **41%**。
中英在这一点上又不是一个体系 —— 与 §5.1.1 的结论同源。

##### D15：为什么 `说明` 是「整句不演」而不是「换个表情」

| 用法 | 实例（真实语料） | 该演 |
|---|---|---|
| **推断**（≈顿悟） | `这说明笔记链接在 DOM 中存在但不在可视区域内` | 星星眼 ⭕ |
| **元信息 / 流程**（不是情绪） | `同时还要更新 _tmp_scratch/ 的路径说明`<br>`文件名不带 -unsigned 已说明是签名发布产物` | 不该演"兴奋" ❌ |

两种用法**没有可靠的词面差异**（都是"说明"），所以无法像 `其实` 那样简单换表情；
用户 2026-10-11 的取舍是 **"不演"比"演错"好** —— 宠物对着"更新路径说明"演兴奋，
比面无表情更惹人烦。代价是那 6 条推断型也一起被牺牲。

**效果**（同一份语料重跑）：

| 表情 | D15 前 | **D15 后** |
|---|---|---|
| 问号 | 12483（41.4%） | 12734（42.2%） |
| 感叹号 | 6468（21.4%） | 6813（22.6%） |
| **星星眼** | 8484（28.1%） | **2906（9.6%）** |
| **不演（null）** | 0 | **3937（13.1%）** |
| 呆呆眼 | 0（一直被高优先桶挡着） | **1045（3.5%）** ← 让位所得 |
| 生气 / 调皮 / 吐舌 | 1524 / 822 / 388 | 不变 |

⇒ 静音的不只是 3937 条"无表情"，还有 **1762 条让位**给了句子里**真实的第二信号**
（`说明` 常与"嗯 / 或者 / 还是"同现 ⇒ 「犹豫权衡」终于露出 1045 条）。
**这是"让位"逻辑的价值**：不是简单地把表情删掉，而是把被粗桶盖住的信号放出来。

**真机效果**（端口 8126，`zh` 策略，一回合）：`片段=32 过阈=6 拟人化拒=0 入队=3 最高分=0.86`；
3 条 speak 帧均带真 `audioUrl` 与表情标签；`play()` 成功 3 / **失败 0**。

```ts
interface TtsProvider {

  readonly cost: ProviderCost;         // 用于负载哨兵决策（声明式）
  synthesize(text: string, opt: TtsOptions): Promise<ArrayBuffer>;  // → 音频

  netBytesPerCall: number;             // edge ≈ 3e4
}
```

> 保留可插拔形状的理由：让社区能自行接其他后端；但**默认且唯一随包提供的实现是 `edge`**（见 8.3）。

#### 6.3.1 ⚠️ 实现方式锁定：**零依赖自实现**（P0-2 结论）

**不得引入任何 npm 依赖**（含 `ws`、`axios`、`edge-tts` 等）。理由与依据：

| 项        | 事实                                                                                                                     |
| -------- | ---------------------------------------------------------------------------------------------------------------------- |
| npm 生态现状 | `edge-tts` / `msedge-tts` / `node-edge-tts` / `@andresaya/edge-tts` / `edge-tts-universal` **全部依赖 `ws`**（部分还带 `axios`） |
| DSH 运行时  | Node **24.18.1**，自带全局 `WebSocket`（undici），且支持 `headers` 选项 → 协议可自实现                                                    |
| 引入依赖的代价  | bundle 带依赖 → `install_bundle` 要走 pnpm 安装与 build-script 审批，社区用户多一层失败点                                                   |
| 已验证      | `p0/edge-tts-zerodep.mjs` 实测跑通；6/6 样本字节数与本机 Python 版一致                                                                 |

**自实现必须注意的四点**（都是实测踩出来的）：

1. **必须带 `Origin` + `User-Agent` 请求头**，否则服务端直接返回 non-101；
2. `Sec-MS-GEC` 鉴权：`SHA256( str( floor((unix秒+11644473600)/300)*300*1e7 ) + TrustedClientToken ).hex().upper()`；
3. 二进制帧前 **2 字节是 `uint16 BE` 的头长度**，跳过它和头文本才是音频负载；
4. 结束标志是**文本帧**里的 `Path: turn.end`，不是"二进制收完"。

**默认参数（已定稿；实测样音见 `tts-demo/lines-playlist.html` 与 `p0/zerodep-listen.html`）**：

```
voice    = zh-CN-XiaoyiNeural
pitch    = +30Hz           (少女音抬调；音色理由见 8.3 备注)
```

| host 半区（常驻）    | 内存增量 ≤ 20MB；CPU ≈ 0              | 实测   |
| Edge TTS（每次合成） | 不占显存、不占 GPU；CPU 可忽略；仅占网络与约 1 秒墙钟 | 实测   |
| 浏览器 Live2D（稳态） | 主线程每帧工作量须留足余量，稳态帧率不得下降           | 实测   |
| 可选小模型打分        | **是唯一会占用显存的环节**，默认关，低配不建议开       | 设计选择 |
| 磁盘（安装态）        | 整包（含默认模型）不超过 10MB                | 实测   |

### 7.2 负载自适应节流（替代 v0.1 的「三档 GPU 降载」）

> v0.1 的降载是围绕「释放显存」设计的；TTS 改为 Edge 云后**显存已不再是瓶颈**，降载的目标改为**避免与用户的主力负载抢 CPU / 抢注意力**。

| 档          | 触发条件              | 行为                        |
| ---------- | ----------------- | ------------------------- |
| **静默**     | 用户手动静音 / 检测到系统高负载 | 只显示气泡文字，不合成、不播放           |
| **标准**（默认） | 常态                | 规则筛选 + Edge 合成 + 朗读，遵守节流闸 |
| **活跃**     | 用户显式调高频率          | 放宽节流闸（仍受 R1 阈值约束）         |

### 7.3 四道节流闸

1. **频率闸**：默认任意 **20s** 内最多朗读 1 句（**D3 已定，2026-10-11**）。
2. **长度闸**：过短（无信息）与过长（听着累）的片段直接丢弃（⚠️ 因实测思考中位 1295 字，这道闸必不可少）。
3. **负载闸**：定时探针（默认 10s）读系统占用；**高于阈值时自动降为静默**，回落自动恢复。
4. **静音闸**：一键静音 / 暂停 / 关闭（红线 R5），状态持久化。

### 7.4 验收阈值（R1 的量化定义，可回归）

| 指标          | 稳态阈值（8G 显存 / 16G 内存机器）    |
| ----------- | ------------------------- |
| 额外显存        | **≤ 150MB**（禁用可选小模型时）     |
| 额外 GPU 利用率  | **≤ 3 个百分点**              |
| 额外 CPU      | **≤ 0.5 个核心**             |
| 额外内存（含浏览器侧） | **≤ 80MB**                |
| 帧率影响        | **稳态不掉帧**（vsync 封顶下不掉出上限） |
| 网络          | 仅朗读时产生；不朗读时 ≈ 0           |

> 未达标 ⇒ 按红线 R1 视为返工，不接受"能跑就行"。  
> ⚠️ 当前仅在**本机高配**验证达标；低配机复验是 **V4**（已顺延到 P5-4）。

#### ❗更正（同日稍后）：H4「指令无效」是**错的**，实际有效且效果很大

**错在哪**：H4 只用本地 `qwen3.5:9b`（Ollama）试了四组系统提示就下了普遍结论。
但**真正要跑的模型是 DSH 里的 `deepseek-flash`** —— 它在这一点上和 qwen 完全不同。

**⇒ 结论：在 DSH + DeepSeek 这条真实链路上，"用中文思考"是可以做到的。**

把一个**模型相关**的现象写成了**普遍**结论。

`order: -90` 落在 `harness:identity(-1000)` 之后、`deployment:persona-prefix(0)` 之前，
即"模型读到的最早一条行为指令"。

**三个实测踩出来的坑**（完整记录见 `p0/inject-probe/README.md`）：

| 坑 | 症状 | 正解 |
|---|---|---|
| 插件 `package.json` 缺 DSH 元数据 | 报 `REQUEST_EXTENSION: DeepSeek request extension preparation failed` —— **伪装成 LLM provider 的问题**，极难定位 | 补 `dsh` 字段 + `peerDependencies` 声明 `@deepseek-ai/dsh-system-prompt`（我们根 `package.json` 已有前者，只需补后者） |
| section 名与社区插件撞名 | 插件级 ctx 落在 `global` 层，同层同名 `insert()` **直接 throw** | 用自有前缀：`think-voice:reasoning-language` |
| 把 `systemPrompt` 放进声明式 `inject` | 没有该服务的 profile 里，**插件整个不激活**（桌宠也不显示） | 用 `ctx.inject(['systemPrompt'], cb)` 软探测 |

**若要自带，三条设计约束（拟）**：
1. **默认关**，由用户在设置页显式开启（接 R5 的开关体系）
2. **留痕**：注入与关闭都记一条日志，用户能看见"插件动了系统提示"
3. 只注入**一句最小约束**，不叠加人格 / 风格 / 其他规则

> ⚠️ **与 R2 的张力**：本插件定位是"**只**读思考（不读正文）"，而注入系统提示是"**写**用户环境"。
> 这是刻意的越界，因此必须默认关 + 可一键关 + 留痕。
